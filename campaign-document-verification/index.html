1a Document verification flow

The screen after a draft is created. It names exactly what is missing, keeps every request in one checklist, and shows where each file stands with the review team.

Assumptions
  • The draft is saved before this step, so nothing is lost by finishing later.
  • Requirements are decided server-side; the beneficiary answer from the campaign form adds the patient set.
  • Review is per document, not per campaign, so one rejection does not reset the rest.
  • Only the verification team sees uploads. Worth saying on screen.
